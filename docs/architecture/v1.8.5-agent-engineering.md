# ResearchForge V1.8.5 Agent Engineering Architecture

## System boundary

```text
User / MCP / n8n / Web
        |
        v
ResearchForge API + lifecycle
        |
        v
Bounded LangGraph Research Agent
  |         |          |
  v         v          v
Discovery  Retrieval  Deterministic finance
  |         |          |
  +------ Evidence / Facts / Calculations -----+
                                                |
                                                v
                                     Model synthesis / fallback
                                                |
                                                v
                               Claims + Result + sanitized Trace
                                                |
                                                v
                                      Agent Eval / Failure Analysis
```

The architecture deliberately has one research engine. Web, n8n and MCP are transport surfaces. They do not own finance formulas, evidence truth or a second reasoning pipeline.

## V1.8.5 engineering loops

### Research loop

`Question -> Router -> Plan -> Official filing -> Evidence retrieval -> deterministic calculations -> synthesis -> validation -> persisted result/trace`

### Evaluation loop

`Frozen case or persisted Run -> Router/Retrieval/Final-answer/Trajectory checks -> measured failure -> taxonomy -> regression candidate`

### Security loop

`Dependency lock -> pip/npm audit -> source allowlists + redirect revalidation -> localhost packaging -> CSP/security headers -> CI`

## Technology ownership

- **Python / FastAPI / Pydantic**: API, lifecycle and contracts.
- **LangGraph 1.x**: bounded orchestration, checkpoint/recovery and traceable stages only.
- **Deterministic Python + Decimal**: financial calculations and period semantics.
- **OpenAI Responses API**: bounded language synthesis over supplied evidence/facts/calculations.
- **React / TypeScript / Vite**: research workspace and audit-on-demand UI.
- **PostgreSQL / Alembic + content-addressed artifacts**: persistence boundary.
- **n8n**: optional external automation transport over the same backend.
- **MCP Python SDK**: thin agent/tool interoperability layer over the same backend.
- **pytest / mypy / Ruff / Playwright / Docker / GitHub Actions**: engineering verification.

## Why MCP is thin

The MCP server exposes seven bounded tools and calls existing ResearchForge APIs or discovery/retrieval components. This avoids the common failure mode where an MCP layer quietly becomes a second business implementation with different source, validation or calculation rules.

## Why Retrieval did not jump directly to pgvector

The project had a prior architecture rule: add vector infrastructure only after a frozen retrieval evaluation shows value. V1.8.3 produced the first measured comparison. TF-IDF improved the current small suite, while naïve RRF traded precision for recall. That is evidence to expand the benchmark, not evidence to add a database dependency yet.

## Honest evaluation boundary

V1.8.5 can verify routing, plan completion, claim grounding, citation existence, structured-output validity and trajectory completion deterministically. It does not claim that these metrics alone prove semantic correctness or analyst usefulness. A future model-judge or human rubric would be a separate, explicitly versioned evaluation layer.
