# V1.7.3 Owner Runtime Isolation & Synthesis-ID Hotfix

**Date:** 2026-09-06
**Status:** engineering verified; owner re-acceptance pending

## Why this correction exists

Owner re-testing after the V1.7.3 reliability gate exposed two independent runtime failures. First, the live Owner API container still carried `RESEARCHFORGE_REASONING_MODE=deterministic` even though `.env` and a newly rendered Compose config both said `auto`; Docker had frozen the old environment when the container was created. Second, after the Owner stack was correctly recreated in model mode, two representative CN General Research runs failed structured-output validation because the model cited Evidence IDs outside that run's retrieved context.

Neither failure changes the V1.7 research scope. This hotfix makes the existing synthesis/fallback boundary and audit promises operationally enforceable.

## Runtime isolation

- `scripts/start_demo.py` force-recreates the Owner API/Web stack and then reads `/v1/runtime-capabilities`; startup fails if the actual running API mode differs from the requested mode.
- `/v1/runtime-capabilities` exposes only safe capability metadata: version, reasoning mode, whether model synthesis is configured, and whether research output is `model_synthesis` or `evidence_only`. No credential material is returned.
- The Web header surfaces `AI READY`, `EVIDENCE ONLY`, or the transient capability-check state before research is started.
- `scripts/container_gate.py` runs deterministic packaging smoke in the isolated Compose project `researchforge-gate`, on ports 18000/14173 with separate volumes. It tears down that project after the gate and cannot mutate the Owner stack on 8000/4173.

## Fallback semantics

A completed deterministic run is no longer presented as a successful AI research synthesis. Web and n8n label it as `EVIDENCE ONLY`; the report uses an Evidence Inventory instead of pseudo Key Findings/Deep Analysis. The overall judgment is `AI Synthesis Unavailable`, reserving `Insufficient Evidence` for cases where the evidence itself is insufficient. Raw facts, Evidence and Trace remain auditable on demand.

## Structured-output ID boundary

For General Research, the OpenAI Structured Output schema now derives runtime enums from the exact bounded context supplied to that request. Finding and analysis `evidence_ids` may only reference selected/counter Evidence IDs, and Finding `fact_ids` may only reference verified Fact IDs. Existing graph validation remains as defense in depth. A failed repair records only the safe validation rule that failed, never raw model prose or hidden reasoning.

## Verification

After the correction, the Owner runtime reported `auto + model_synthesis`. The exact research categories that exposed the issue were rerun against official-source packages:

- 贵州茅台 profitability / financial-health question: `synthesis_mode=model`, 6 Claims, 5 analysis sections, `Supported`.
- 大华股份 growth-driver question: `synthesis_mode=model`, 6 Claims, 5 analysis sections, `Supported`.

The isolated deterministic container gate then passed all three reviewed-cache smoke cases while the Owner runtime remained `auto + model_synthesis` before and after the gate. Full backend/frontend/n8n/contract checks also passed. The actual n8n 2.37.9 runtime was re-exercised after the hotfix: three success cases, idempotent replay, minimum cached input, native form/failure rendering, five HTTP failure checks and all five transport-only failure scenarios passed. These engineering facts do not complete Owner Acceptance; `RELEASE_FREEZE` remains pending the owner's manual re-acceptance.
