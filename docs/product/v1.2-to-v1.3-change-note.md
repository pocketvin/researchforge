# ResearchForge V1.2 → V1.3 Change Note

- Decision date: 2026-08-30
- Status: accepted by project owner request

## Why V1.3 Exists

V1.2 provided a strong research definition but deferred all value until a broad product and a successful Evolution outcome. It also named LangGraph and pgvector without fully defining their architectural necessity, froze a five-object database list that omitted evidence persistence, and lacked an explicit data-feasibility gate and project-resumption contract.

V1.3 keeps the valuable research thesis while making the project more feasible, useful, testable, employable, and recoverable for a solo builder.

## Supersession

- `researchforge-v1.3-scope.md` is the active product/research authority.
- `researchforge-v1.2-scope-freeze.md` remains an immutable historical source and is not edited.
- Active semantic contracts move to package `1.3.0`.
- V1.2 schemas remain under `schemas/v1.2/` for historical compatibility.
- New work persists V1.3 artifacts under `schemas/v1.3/` with `schema_version: 1.3.0`.

## Material Changes

| Area | V1.2 | V1.3 |
|---|---|---|
| Scope governance | Frozen document | Versioned active baseline; changes require explicit decision/changelog |
| Personal success | Full product and successful Evolution dominated completion | L0–L4 independently valuable; research failure can be reported honestly |
| First implementation | Broad stack implied | One earnings-quality Portfolio MVP after a data-source gate |
| LangGraph | Named for Research Workflow | Required but bounded single-agent orchestration contract with graph version and trace |
| Financial/domain logic | Correctness required | Explicitly prohibited from living in LangGraph nodes |
| Data feasibility | Provider mapping in G0 | Time-boxed license/semantics/reconciliation decision before infrastructure |
| Retrieval | pgvector in fixed stack | Deterministic baseline first; pgvector conditional on retrieval evidence |
| Persistence | Five database objects only | Five core records plus three supporting provenance/artifact records |
| Product usefulness | Narrative success criteria | Golden correctness, reliability distribution, efficiency, and target-user pilot |
| Recoverability | Not machine-contracted | Project Checkpoint schema, one WIP, resume playbook, one next action |
| LangGraph evidence | No dedicated persisted schema | V1.3 Workflow Trace artifact and explicit Run Manifest workflow configuration |

## Preserved Scope

- one single Research Agent;
- five product research tasks;
- one core fundamental-research skill;
- earnings-quality omission as the only Evolution target;
- Base/Seed/Candidate controlled comparison;
- sealed Final Test and leakage prevention;
- two-page full-product demo;
- no investment advice, trading, prediction, multi-agent debate, or open-ended optimization.

## Compatibility Policy

V1.2 artifacts are read-only historical evidence. A V1.2 artifact is not silently treated as V1.3. Any future migration must:

1. preserve the original artifact and hash;
2. create a new V1.3 artifact with a migration record;
3. validate against the V1.3 schema;
4. disclose defaults or fields that could not be reconstructed.

No runtime migration is implemented in this contract-only upgrade.
