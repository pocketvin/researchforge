# ResearchForge V1.7.2 → V1.7.3 Reliability & Audit Hardening

**Date:** 2026-09-05
**Status:** Engineering hardening in final verification; Owner Acceptance remains separate.

## Why this version exists

V1.7.2 closed the visible workspace UX gaps, but a project-wide audit found several reliability boundaries that were weaker than the product promise. The most important issue was lifecycle ordering: autonomous source discovery could happen before a durable Run existed, so provider latency, cancellation, restart recovery and audit state were not represented by one authoritative lifecycle.

V1.7.3 does not broaden the research product. It hardens the existing General Company Research path so the runtime behaves like the audit story already promised.

## Lifecycle correction

Autonomous Research now persists a `queued` Run before any official-source discovery or filing acquisition begins. The same Run then owns preparation, graph execution and terminal state:

```text
submit → durable queued Run → preparation/discovery → research graph → terminal state
```

A new V1.7.3 Run Manifest schema records preparation state, provider/package identity and bounded failure information. Preparation failure or cancellation before LangGraph starts no longer fabricates a workflow Trace.

Dynamic company/package context is persisted so interrupted autonomous runs can recover after process restart without silently falling back to the static catalog or changing the requested company.
## Concurrency, restart and budget integrity

- Run execution uses run-scoped file locks so API background execution and restart recovery cannot execute the same Run concurrently.
- API startup recovery is dispatched in the background; a slow interrupted Run cannot block `/healthz` or application startup.
- File-backed idempotency is atomic across repository instances instead of only within one Python object.
- Budget reservation is atomic across `BudgetLedger` instances that share the same state file.
- The autonomous deadline is derived from the original persisted submission time, so restart does not reset the total execution window.
- Terminal runs remove their LangGraph checkpoint thread from the shared checkpoint store to prevent unbounded checkpoint accumulation.

## Source and exposure hardening

Official-source redirects are revalidated after HTTP redirect resolution. SEC, HKEX and discovery JSON fetches reject a final non-official host even when the initial URL was allowlisted.

The unauthenticated packaged Web/API surface binds to `127.0.0.1` by default rather than the whole LAN. Model cost configuration is restricted to the model with an explicit pricing contract, and the per-run model bound now includes the allowed structured-output repair request.

Investment recommendations, buy/sell instructions and target-price requests are rejected at the public research boundary rather than relying on a narrower task-mode check.

## Product-surface reliability

Recent Research history now supports offset pagination and the Web can load additional persisted runs instead of silently slicing the first eight records. Queued autonomous runs retain the submitted company/market/period context before facts exist, so history does not show a blank or unrelated company while preparation is still running.

The historical Quality/Evolution experiment used by the methodology archive is packaged as a read-only repository asset. Opening the method archive no longer depends on an old mutable local artifact volume.
## Contract compatibility

The General Research Result schema remains `1.7.0`; V1.7.3 introduces a new lifecycle manifest contract at `schemas/v1.7.3/run-manifest.schema.json`. Historical V1.7, V1.5, V1.4 and older artifacts remain preserved and valid under their original schemas.

The n8n public route IDs remain `researchforgeV17`, `/webhook/researchforge-v17` and `/form/researchforge-v17-form` for compatibility. The workflow now requires backend product version `1.7.3` but still transports the same authoritative backend research artifacts.

## Verification target

V1.7.3 is complete only after the normal project gates pass: lock/format/lint/typecheck/tests, contract validation, frontend unit/build and mocked/live E2E, n8n generation/tests/runtime, fresh Docker smoke, bounded failure fixture, source/exposure checks and final Git diff/secret review.

The specific reliability regression covers queued-before-discovery, restart recovery with persisted company context, provider failure without fake Trace, cancellation before discovery, cross-instance idempotency, cross-instance budget reservation, concurrent run execution and checkpoint cleanup, official-source redirect rejection, non-blocking startup recovery, history pagination and packaged method artifacts.

## Release boundary

V1.7.3 does **not** mark `RELEASE_FREEZE` complete. Engineering verification may prove that the implementation is reliable; only the owner can accept the final product experience. The first failed V1.7 acceptance and the later V1.7.1/V1.7.2 corrections remain part of the project history.

## Non-goals

V1.7.3 does not add real-time news, broker research, price targets, trading, portfolio management, universal filing-layout support, multi-agent debate or a second research engine. It is a reliability and audit hardening release over the already frozen General Company Research direction.
